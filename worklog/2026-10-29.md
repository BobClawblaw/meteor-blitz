# 2026-10-29

## HD art path

Picked up the uncommitted HD work from the previous session: `tools/upscale4x.py` and `assets/4x/` were generated, and `gfx.rs`/`hud.rs`/`pause.rs` had partial scale handling, but the tree did not compile (`Font::new` arity) and the loaders still read `original/` and `assets/ui/`, so no 4x art was actually loaded.

### Changed

- `src/gfx.rs`: `asset_scale()` (MB_HD=0/1, default 4 on desktop, 1 on wasm) and `tex_size()`; `draw_quad`, `draw_sprite` and `draw_atlas_sprite` now lay art out at the original logical size.
- `src/main.rs`: `art_path()` routes every loader (`load_ui`, `load_sprite`, `load_texture_file`, the font `.dat`) to `assets/4x/` when HD is on; the menu backdrop goes through the same loader so `MB_BG_BASE`/`MB_BG_DECAL_TEX` still work.
- `src/hud.rs`: `Font` takes the atlas scale and divides glyph metrics for drawing and advance, so text keeps its original size from the 4x atlas.
- Layout sites that centred or spaced art from `tex.width()` now use `tex_size()`: menu labels, help captions, depot/power labels, the name-entry label; tutorial captions and HUD counters draw through `draw_quad`.
- `src/pause.rs`: nine-slice source rects scale with the atlas, the slider knob keeps its 25x25 destination, and the popup quads go through `draw_quad`.
- `tools/upscale4x.py`: terrain/fog/space textures are generated at 2x instead of 4x. The backdrop mesh minifies them across the screen and macroquad 0.4 builds no mipmaps; 2048x2048 sampling dropped the frame rate to 46-57 fps. Sprites/UI/font stay 4x.
- `assets/4x/` committed (546 files, 79 MB) so the game runs without the upscale step; `README.md` and `AGENTS.md` document `MB_HD`, the regeneration command and the web build staying on the originals.

## Pause label fidelity against the emulator frame

Follow-up to the HD work: the pause popup's buttons were pixel-exact but its labels were too small and too crisp. Measured in `original/screenshots/emu/frame_00030.png`: the emulator's "Resume" label is 70x8 px, the port's was 53x6 at the old 0.4 nearest scale, i.e. about 1.35x too small and unblurred.

### Changed

- `PauseAssets` now carries its own `label_font`: the original 1x `ngage` atlas with linear filtering, matching the engine's low-resolution rasterised label texture instead of the HUD's crisp glyph quads. All popup text (titles, button labels, upgrade captions) uses it; the HUD and score screens keep the HD/nearest font.
- `fit_scale` default is 0.54 (was 0.4) and `label_dy()` adds the measured +1 px vertical offset; `MB_LABEL_DY` overrides it.
- `Font::set_filter` added so the pause atlas can opt into linear filtering.

### Verified with real output

- Scale/offset/filter sweep against `frame_00030.png` (480x320, MB_HD=0): summed button-region diff 80.3 for 0.4 nearest, 55.8 for 0.54 + 1 px + linear. Per-button optima (flip 0.54, resume 0.54, quit 0.60, upgrade 0.52, controls 0.56) summed to 49.5, but no simple per-button fit beat the fixed scale, so the fixed value stays.
- Whole pause frame: 13.12 with the originals (was 14.83) and 13.18 with HD art (was 14.18); the "Paused" title region dropped 13.35 -> 8.58.
- Text bboxes checked on every page at 480x320: menu 114x8/71x7/39x7/84x7/96x8, controls 87x7/47x7, quit 71x7/39x7, clear and game-over 87x7 — all inside their button rects.

## Web build verified in a browser

The web build had never been checked past "it compiles". No touchHLE here, so this was the next doable item.

### What was wrong with the naive check

`Chrome --headless --screenshot --virtual-time-budget=...` writes a black canvas: virtual time leaves the game's requestAnimationFrame frames unpainted, and `readPixels` after present returns a cleared buffer. Driving Chrome over the DevTools Protocol with real time works.

### Added

- `tools/web_screenshot.mjs`: starts its own headless Chrome (swiftshader), navigates, waits real time, optionally clicks X,Y pairs to walk the menus, and captures through `Page.captureScreenshot`. Usage in `README.md`.
- `AGENTS.md`: web verification note and the virtual-time caveat; Next list updated (only the pause main page has an emulator reference frame).

### Verified with real output

- Menu at 480x320: the web capture is 480x320, mean 42.5-42.9, 3555-3559 bright pixels; against the native `MB_HD=0 MB_MENU=main` capture the four buttons differ by 0.14/0.15/0.35/0.18 mean abs, i.e. the same rendering; the whole-frame 5.47 is the backdrop scroll phase (the web run was ~12 s in, the native shot at frame 300).
- Gameplay: clicks at (240,240) Play, (134,182) Arcade, (95,112) World 1, (93,115) Stage 1 reach the game screen in the browser — mean 34.7, 1528 bright pixels, 45981 colours, HUD and the ship/rock art present. So the sprite and terrain assets load in the wasm build too.
- The page reports `WebGL 1.0 (OpenGL ES 2.0 Chromium)` and a 480x320 canvas under the device-metrics override.
