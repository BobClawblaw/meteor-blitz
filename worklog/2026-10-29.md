- `src/pause.rs`: nine-slice source rects scale with the atlas, the slider knob keeps its 25x25 destination, and the popup quads go through `draw_quad`.
- `tools/upscale4x.py`: terrain/fog/space textures are generated at 2x instead of 4x. The backdrop mesh minifies them across the screen and macroquad 0.4 builds no mipmaps; 2048x2048 sampling dropped the frame rate to 46-57 fps. Sprites/UI/font stay 4x.
- `assets/4x/` committed (546 files, 79 MB) so the game runs without the upscale step; `README.md` and `AGENTS.md` document `MB_HD`, the regeneration command and the web build staying on the originals.

### What was wrong with the naive check

`Chrome --headless --screenshot --virtual-time-budget=...` writes a black canvas: virtual time leaves the game's requestAnimationFrame frames unpainted, and `readPixels` after present returns a cleared buffer. Driving Chrome over the DevTools Protocol with real time works.

## Regression fixes: backdrop tiling, controller focus, name entry

Reported after playing the HD build: a checkerboard on the background, no visible controller selection in menus, and a name prompt interrupting a stage clear.

### Backdrop checkerboard

- The backdrop shader wraps the layers (`fract(uv + Scroll)`), so the textures must tile. The ESRGAN output did not: edge continuity was 16-125 mean abs versus 0.5-8 for the originals, and the ncnn tool's automatic 400 px tiling left internal seams at x/y 399/799.
- `tools/upscale4x.py`: the ncnn tool now runs one tile (`-t 1024`), and the ESRGAN detail is blended into a periodic Lanczos base (a 3x3 tiled resize cropped at the centre) over a 24 px edge band. A Lanczos fallback is also periodic.
- Verified on the regenerated set: edge diffs L-R/T-B 0.38-3.74 for every texture except clouds (9.96/13.62, against the original's own 20.25/30.79); no internal peaks above 5x the median. `MB_FPS=0 MB_PROF` still holds 60 fps with draw 0.14 ms.

### Controller focus in menus

- The menus drew the focused button's "down" texture, but the world/stage screens reuse one texture for up and down, so nothing showed. The original was touch-only; the port's focus needs an indicator.
- `MenuScreen::draw` now draws the pause popup's 1 px white frame around the focused button, and Back is the last entry in each menu so the first stick/D-pad press lands on the first option (Play/Arcade/World 1/Stage 1) instead of Back.
- Added `MB_FOCUS=<n>` for captures. Verified: with `MB_MENU=main MB_FOCUS=1` the changed pixels are exactly the High Scores button border (bbox 31,352-287,607 at 960x640), 58k pixels.

### Name entry timing

- The trigger checked `scores.qualifies` for every `Play::result()`, so clearing any stage opened `labelEnterName` mid-run. It now opens only when the run ends: game over, or the final stage cleared with no next stage.
- Verified: `MB_START=1.1 MB_WAVE=99 MB_AUTOFIRE=1 MB_FPS=60 MB_NAME=BOB` now reports `shot: pause true name entry false` and leaves `scores.txt` unchanged. The idle game-over run still reaches the name step (checked separately).

## 120/144 Hz verified

- Found: macOS miniquad paces frames with `CVDisplayLinkCreateWithActiveCGDisplays`, i.e. the main display's refresh (60 Hz), wherever the window is, so the 120/144 caps could never show (the earlier note that a 120 Hz panel would get 120 was wrong). ## Input under the blocking event loop

- Tried synthetic keyboard input (a CoreGraphics `CGEventPost` tool; `osascript` lacks assistive access here) against Options (Down + Return should toggle widescreen in settings.txt): no effect with the new build, and none with the previous build (pre-0c8d501, display-link loop) either, so this machine drops injected input; unattended input testing is not possible here.
