## 04:30 — Ghidra + touchHLE installed; original runs in the emulator; textures were colour-swapped

**Changed:**
- Installed Ghidra 12.1.4 (Homebrew, with OpenJDK 21) and ran a headless decompile of the whole binary: 1,480 functions as C in `~/tools/ghidra-projects/meteor-blitz-decomp/` (script `~/tools/ghidra-scripts/DecompileAll.java`).
- touchHLE v0.3.0 built from source at `~/tools/touchHLE-src` (needs Boost and `CMAKE_POLICY_VERSION_MINIMUM=3.5` for CMake 4) with three local patches: NSThread retains itself while running (the game releases its run-loop thread right after `start`, which crashed), `GL_POINT_SIZE_ARRAY_OES` client state and `glPointSizePointerOES` are tolerated (per-vertex point sizes are ignored, so bullet/particle sizes in the emulator are wrong), and `TOUCHHLE_DUMP_FRAMES_DIR` dumps every 30th presented frame as PPM. The release binary also needs `tools/emu_prepare.py` (NOPs the thread-priority calls).
- All PVRTC decodes redone with PowerVR's reference decoder (`tools/pvr_decode.cpp`, `tools/decode_textures.py`, `tools/decode_sprites.py`): the earlier texture2ddecoder output had red and blue swapped on every texture and sprite (difference exactly 0 after swapping channels back).
- Menus rendered through the original pipeline (`src/menu.rs`): gluPerspective 60° / eye z 414.988 into a portrait 320x480 target, landscape rotation matrix, backdrop mesh (16x16 cells of 64 on a radius-700 sphere, `space4deep` with `fogRed` GL_DECAL) at (240,155,100), horizon at z 0 scale 1.25, screen content at z 150.
- Web page: `const canvas` clashed with the JS bundle's own `canvas`, so the page script died and keys never reached the game. Renamed; unfocused key events are forwarded too.
