## Resume status (2026-10-28, macOS controller verified)

Done (faithful to the binary unless noted):
- Menus, game screen, HUD, sounds, particle effects (`systems.dat`), rings, multiplier, power-ups.
- Every enemy kind in the wave tables: rocks, depots, mines, shy guys, snakes, arrows, towers, seekers, lobbers, boss.
- Bombs, fire and laser weapons (levels by world), gravity gun.
- Pause, controls, upgrade, clear and game-over popups from `PausePopup`: layouts and gradients match the decompiled draw code; keyboard/mouse navigation; upgrade shop; survival auto-upgrade toggle.
- Deliberate change from the original: the planet backdrop scrolls at the play plane's screen speed, so rocks stay glued to the ground (`gfx::glued_scroll`). The original's rate let them slide.
- Performance: the loop is paced at 60 Hz (the original's simulation rate); macOS controller polling no longer posts a LaunchServices KVO notification every frame.
- Rendering: the offscreen canvas renders at the window's fitted resolution (1:1 blit) instead of upscaling the original 320x480 framebuffer; `MB_RENDER_SCALE` pins it (1 keeps emulator comparisons exact). The bitmap font uses nearest filtering so glyphs stay crisp above 480x320; `MB_FONT_FILTER=linear` opts out.
- HD art (desktop): 4x sprites/UI/font atlas and 2x terrain textures from `tools/upscale4x.py`, loaded by default; `MB_HD=0` loads the originals and is what emulator-frame comparisons use. The web build keeps the originals (the 4x set is ~79 MB). Terrain stays at 2x because macroquad builds no mipmaps: sampling 2048x2048 backdrops dropped the frame rate to ~46-57 fps, while 2x holds 60 Hz (draw 0.2 ms). The backdrop shader wraps (`fract`) these textures, so `upscale4x.py` fades the ESRGAN detail into a periodic Lanczos base near the edges and runs the ncnn tool in one tile; raw ESRGAN output does not tile and showed as a checkerboard grid.
- Web build: published with GitHub Pages from `main` at the repo root (https://bobclawblaw.github.io/meteor-blitz/); `index.html` is the game page (`web.html` redirects to it), `.nojekyll` skips Jekyll. The game's data loads as one pack: `tools/web_pack.py` (run by `tools/build-web.sh`) writes `web/data.pack.gz` (571 files, 13.6 MB, deterministic; was 24.1 MB before the audio and PNG work), the page downloads it with a progress bar and a plugin answers miniquad's `fs_load_file` from it (fallback: a normal request). Loading the files one by one took minutes on Pages (hundreds of sequential round trips, black screen); with the pack a load is 4 requests. Controllers work in the browser: `index.html` registers a miniquad plugin whose `mb_gamepad_read` writes the first connected pad's 4 axes and 17 standard-layout button values into wasm memory, and `pad.rs`'s web `raw` module feeds the shared backend (presses, stick menu navigation, bindings). `MOCK_PAD=1 node tools/web_screenshot.mjs ...` fakes a pad: verified 2026-10-29 that its A presses walk the menus into stage 1.1 and its stick moves the ship. Rebuild the bundle (`tools/build-web.sh`) and commit `web/meteor-blitz.wasm` with any change the web should get.
- Web build verified 2026-10-29 with `tools/web_screenshot.mjs` (headless Chrome over CDP): at 480x320 the menu buttons differ from the native `MB_HD=0` build by 0.14-0.35 mean abs (the backdrop differs only in scroll phase), and clicking through Play > Arcade > World 1 > Stage 1 renders gameplay with the sprite/terrain assets loaded. Use real time, not `--virtual-time-budget`: virtual time leaves the first frames black.
- Modern display (2026-10-29; the port's goal is now a modern port, see `docs/port-plan.md`): the window is resizable; F11 or Alt+Enter toggles fullscreen (`settings.txt` `fullscreen`). The view follows the window's aspect from 3:2 to 2.4:1 (`gfx::view_w`): screens still draw in 480x320 coordinates, centred, and the camera widens (same play-plane scale), so the play field shows more to each side. `gfx::edge()` is the extra width per side: the HUD's corner items, the pause bands, flashes and edge-anchored tutorial panels use it; `Canvas::mouse` returns canvas coordinates (x may be negative). The game planet's sphere grows with the view (radius x wide^1.5) so its limb stays off screen; the centre, and so the glued ground scroll, is unchanged. The menu horizon continues its dark side to the left edge. The render target and backdrop meshes are rebuilt when the window size or aspect changes.
- Bloom (port addition, `settings.txt` `bloom`, on by default) is emitter glow: while the world draws (`Canvas::set_glowing`, off before the HUD), every additive draw (shots, flames, sparks, explosions, the gravity cone) is recorded, plus laser bolts and tower beams (`Canvas::add_glow`); at the blit they are redrawn into a quarter-resolution buffer, blurred (two rounds of a 9-tap separable Gaussian) and added at strength 1.25 (`gfx::Bloom`). Bright clouds and the HUD never glow. Off while the pause popup is up; `MB_BLOOM=0` forces it off.
- Frame rate (port addition): Options > Frame rate cap (60/120/144, `settings.txt` `fps`, default 60) paces drawing; the simulation stays at a fixed 60 Hz. `Play::update` snapshots every drawn position before each step (`Snapshot`) and draws `blend` of the way from it to the current state (camera, scroll, ship, every enemy list, rings); a list whose length changed in the step draws unblended that frame, and bullets step back along their velocity instead. miniquad's macOS frame pacer is a CVDisplayLink created on the main display (60 Hz here, wherever the window is), so on macOS the window runs miniquad's blocking event loop instead (no display-link pacer), paced by `frame_timer` (main.rs): a repeating default-mode run-loop timer at the cap schedules the next frame and posts an empty application event, so the loop waits in `nextEventMatchingMask` between frames. The run loop must turn there, outside any frame: `pad.rs` used to pump it inside the frame (for GameController's main-queue updates), and a click on the menu bar then opened the menu mid-frame, AppKit redrew the window, a second frame started inside the first and macroquad aborted ("Only one active query"; fixed 2026-10-29, reproduced and verified with a timer that opens and cancels the app menu). Windows and Linux keep the sleep pacer; measured on this Mac: 60.1, 119.9 and 144.0 fps for caps 60/120/144 from `settings.txt`, and a fixed world point moves a steady 2.1-2.4 px per frame at 144 fps while the blend cycles. `MB_FPS` overrides the cap.
- Lighting and effects (port addition, Options > Lighting and effects, `settings.txt` `visual_fx`, default on; `MB_FX_OFF=1` forces off): the game backdrop shader takes a normal map per planet (`tools/normalmaps.py` -> `assets/normals/`, `assets/4x/normals/`, brightness as height, wrap-around gradients) lit by a fixed key light from the upper left (clouds flatten it), plus up to 12 point lights on the canvas (`gfx::Light`): fading glows from explosions, hits, bombs, the boss and ship deaths (`event_light`), shots (every 2nd-4th bullet), and the ship. The backdrop vertex shader maps clip space back to the canvas (`ndc_to_canvas`, unit-tested). Enemy, rock and ring sprites use the `lit` material, tinted by the same lights (`Play::tint`, vertex colour 0.5 = unlit).
- Post effects (with Lighting and effects): the final blit runs `POST_FRAGMENT`: up to 4 shockwave rings (`gfx::Wave`; bombs, the boss dying and dead, depots, the ship's death, large and extra-large rocks via `event_shock`; a ring grows with ease-out and fades) bend the image with a slight colour split, then per-world colour grading (`world_grade`: lift, gain, saturation) and a 0.25 vignette. Menus keep the plain blit.
- Scorch marks (with Lighting and effects): destroyed rocks (by size), enemies, depots and the boss leave burn marks on the play plane (`event_scorch`; texture generated at startup by `play::scorch_texture`), up to 96, lasting 15 s and fading over the last 5.
- Ship effects (with Lighting and effects): a green engine trail (16 samples, shown in proportion to speed), boost speed lines, a pulsing shield rim, short streaks behind cannon and laser shots (0.03 s of flight), and streaks behind enemies the gravity gun threw (`draw_ship_fx`, `draw_shield_rim`), all additive so they glow.
- Soft particles (with Lighting and effects): `systems.dat` point particles, square GL points in the original, draw as round Gaussian embers (core x1.8 plus a faint halo x3.5 at 12%) and line particles as 2.5-unit soft streaks, through `play::soft_dot_texture`; shards/diamonds keep their shapes. Ground light saturates softly (`light / (1 + light)`) so overlapping flame lights do not wash the ground out.
- Project link (port addition): the main menu shows the GitHub mark (`tools/github-mark.svg` rendered by `tools/make-github-mark.py` with `rsvg-convert`; `brew install librsvg`) and `github.com/BobClawblaw/meteor-blitz` under the buttons, as menu button event 4 (mouse or controller focus + A); it opens the page in the default browser (`open` / `explorer` / `xdg-open`; nothing on the web build). The address is set in Rajdhani Bold (`assets/fonts/`, SIL OFL with `OFL.txt`, built into the binary) because the ngage font has no '/', '.' or '-'; it is rasterised at the canvas target's pixel size (`gfx::pixel_scale`) and drawn at 1/k, so it stays sharp at any window size.
- Release packaging (1.0.0): `paths::init` finds the data in the repo (working directory), via `MB_ROOT`, or packaged beside the executable / in a macOS bundle's `Contents/Resources`; packaged builds save `settings.txt`, `scores.txt`, `save.txt` and `controls.txt` to the user's app-data folder (`~/Library/Application Support/Meteor Blitz`, `%APPDATA%\Meteor Blitz`, `$XDG_DATA_HOME/meteor-blitz`). App icons come from the original 57x57 icon via `tools/make-icon.py` (Real-ESRGAN 4x, `assets/icon/`: `.icns`, `.ico`, 16/32/64 window icons built into the binary). Windows release builds use the windows subsystem (no console) and embed the icon (`build.rs`, `winresource`). Packaging: `tools/package-macos.sh` (universal app + DMG in `dist/`, ad hoc signed; `--app-only` for this Mac, which `tools/make-app.sh` now runs) and `tools/package-windows.ps1` (exe + data zip). The `.app` is self-contained: verified 2026-10-29 that a copy outside the repo, run with an empty environment, renders and saves to Application Support, and that both architectures link only system frameworks.
- Survival (Global::level 6) is ported from `WaveManager` (`Script::survival`, enemies.rs): it never completes; a wave starts 3 s after the last finishes spawning; each wave raises a power budget (8, +1.25) and picks `int(power x random x 0.75) mod 114` from `SURVIVAL`, so harder waves come with the budget; while the budget exceeds the field's power (`Field::survival_power`: rocks 1/4/13/40, shy guy 1, arrow 2, snake 8, mine 1.5, seeker 4, tower 10, lobber 10, depot 1) plus the wave's by 4, the next wave follows at once without counting; wave 8 and every 15th after is a supply depot (`SURVIVAL_DEPOT`) then a pause (`SURVIVAL_WAIT`, both decoded from the static initializer by `tools/extract_waves.py`); deaths, bombs and broken shields take 5 off the budget (not below 8); each wave speeds the game by 1.0003 (TimeManager::baseMultiplier, `TimeScale::base`). Before this, survival played world 6 stage 1's fixed waves and ended as a stage clear.
- Muzzle (deliberate change): shots spawn at the ship's nose, `MUZZLE` (the ship's radius, 10 units) along the aim, instead of at its centre, and anything drawn behind a shot (the cannon's dot trail, the shot streaks, the set-back flame and laser sprites) is clipped to the distance it has flown (`Bullet::flown`), so fire no longer shows out of the ship's tail.
- Asset size (2026-10-29): the web build loads MP3s (`tools/web_audio.py` -> `assets/web-audio/`, LAME VBR, 11.6 MB of WAV -> 1.6 MB; decoded lengths within one sample of the WAVs in Chrome, so the music loops cleanly; `sound_path` in main.rs picks MP3 on wasm, WAV on desktop; the packages leave `assets/web-audio` out). PNGs are recompressed losslessly with `tools/optimize-png.sh` (oxipng; run it after any asset script): `assets/` 74.5 -> 66.1 MB, all 750 files pixel-identical; `tools/web_pack.py` packs oxipng copies of `original/` PNGs (cached in `target/web-pack-png/`, 357/357 pixel-identical).
- Stage advance keeps the run: `Play::advance_stage` starts the next stage in the same screen, carrying score, rings, upgrade points, upgrades, lives, bombs and multiplier, like the original's `GameScreen::handleEvent` next-stage case; only the stage's world state restarts.

Controls:
- Defaults (rebindable, see Options > Controls): WASD moves, left mouse fires toward the cursor, Space boosts, right mouse or B bombs, Q or the wheel switches weapon.
- Gravity gun: double-click, or E, while firing.
- Esc on the main menu quits.
- Pause: Esc (or Start/View, or the pause icon) opens; arrows/WASD move the selection, Enter/A activates, Esc/B goes back; mouse clicks activate items. The music, effects and shake sliders are in the selection order (Left/Right adjust a selected slider by 5%) and can be dragged with the mouse.
- Esc goes back one level everywhere, like B on a controller: Stage > World > Mode > Main, the score table and Options > Main, Controls > Options, a pause sub-page > the pause menu > the game; on the main menu it quits. Leaving the HELP tutorial from its pause menu returns to the main menu.
- Controller menus: the D-pad and the left stick move the selection (the stick steps once per push and repeats while held); A activates, B backs out. The focused button is outlined with a 1 px frame, since the original was touch-only and some screens reuse one texture for the up/down states.
- Game controller: mapped in `src/pad.rs`. Windows reads it through gilrs's XInput backend (verified 2026-10-20: A, B, X, Y, LB, RB, LT, RT, D-pad, both sticks full range; View and Start not yet pressed in a logged run). The default WGI backend dropped most input from the Bluetooth LE pad, and its Drop failed fast on window close; `Gilrs` is kept in `ManuallyDrop`.

Test hooks (env):
- `MB_START=w.s` starts a stage; `MB_WAVE=n` starts at wave n.
- `MB_SHOT` and `MB_SHOT_FRAME` capture a frame and exit.
- `MB_WIDE=0` keeps the original 3:2 view (letterboxed); `MB_WIDE=0 MB_HD=0 MB_RENDER_SCALE=1 MB_BLOOM=0` reproduces the original framebuffer (main menu vs the emulator frame: 7.71 best scan diff, as before the wide view).
- `MB_RENDER_SCALE=<n>` sets the canvas render scale (default: the window's fitted scale, capped at 6; 1 = the original 480x320 framebuffer).
- `MB_HD=0` loads the original art instead of `assets/4x/` (1 forces HD); emulator-frame comparisons use 0. The web build always loads the originals.
- `MB_FONT_FILTER=linear` switches the bitmap font back to linear filtering.
- `MB_PAUSE=<menu|controls|upgrade|clear|gameover>` opens a pause page for screenshot runs; it starts stage 1.1 when no stage is running, so the popup draws over a game. `original/screenshots/emu/frame_00030.png` is the pause main-page reference.
- `MB_LABEL_SCALE=<n>` pins the pause button label scale (default 0.54), for comparing label sizes against the emulator.
- `MB_LABEL_DY=<n>` nudges the pause labels vertically (default 1.0), for matching the emulator's label placement.
- `MB_BG_BASE` / `MB_BG_DECAL_TEX` override the menu backdrop textures (defaults `space4deep`/`fogRed`), for comparing against emulator frames.
- `MB_AUTOFIRE`, `MB_GUN`, `MB_BOMB_AT`, `MB_BOOST_AT`, `MB_WEAPON` and `MB_DRIFT` drive play unattended. `MB_FX_OFF=1` turns Lighting and effects off for a run.
- `MB_FPS=<n>` overrides the 60 Hz frame cap (`0` = uncapped). `MB_PROF=1` prints update/draw CPU per 120 frames; `MB_PROF_FRAMES=n` exits after n frames for benchmarks. Screenshot runs are uncapped unless `MB_FPS` is given, so `MB_SHOT_FRAME` still selects the same state.
- `MB_PAD_LOG` prints controller input. To tell a game bug from a driver one on Windows, run an XInput reader (`XInputGetState` on xinput1_4.dll) alongside and compare.
- `MB_MENU=<main|mode|options|controls|scores|scores-arcade|scores-survival|scores-global>` opens a menu screen directly, for captures (`help` = `controls`).
- `MB_DUMP_SETTINGS=1` prints the settings loaded from `settings.txt` and exits, for checking persistence without a GUI.
- `MB_NAME=<name>` confirms the `labelEnterName` field for scripted runs; `MB_MENU=name` opens it directly.
- `MB_FOCUS=<n>` shows the controller focus frame on the nth menu button in `MB_MENU` captures.
- `MB_TUTORIAL=<step>` starts the tutorial at that step (0 = the start), then World 1 Stage 1; the panel shows once the ~1.7 s fly-in ends (use `MB_FPS=60 MB_SHOT_FRAME=200`).
- `MB_AUTONEXT=1` advances a cleared stage at once (skipping the results/upgrade popups) and prints `advance:` with the carried score, rings, points and upgrades; `MB_BUY=<0-5>` buys that upgrade first, to check that purchases carry.
