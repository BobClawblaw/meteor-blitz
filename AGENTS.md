- Performance: the loop is paced at 60 Hz (the original's simulation rate); macOS controller polling no longer posts a LaunchServices KVO notification every frame.
- Rendering: the offscreen canvas renders at the window's fitted resolution (1:1 blit) instead of upscaling the original 320x480 framebuffer; `MB_RENDER_SCALE` pins it (1 keeps emulator comparisons exact). The bitmap font uses nearest filtering so glyphs stay crisp above 480x320; `MB_FONT_FILTER=linear` opts out.
- HD art (desktop): the 4x set (4x sprites/UI/font atlas and 2x terrain textures from `tools/upscale4x.py`) was the default until 2026-11-02 and is now `MB_HD=1` (see the 8x entry below); `MB_HD=0` loads the originals and is what emulator-frame comparisons use. The web build keeps the originals (the 4x set is ~79 MB). Terrain stays at 2x because macroquad builds no mipmaps: sampling 2048x2048 backdrops dropped the frame rate to ~46-57 fps, while 2x holds 60 Hz (draw 0.2 ms). The backdrop shader tiles these textures, so `upscale4x.py` fades the ESRGAN detail into a periodic Lanczos base near the edges and runs the ncnn tool in one tile; raw ESRGAN output does not tile and showed as a checkerboard grid. A final adaptive edge crossfade (`tileable`) makes the texture's own wrap continuous; without it the fog textures still showed a line at the texture edge (fixed 1.0.7). All textures use the 128px band; the fog textures need it to hide their edge seam. The original sprawl city grid read as banding at 4K, so world 4 now uses the crater base instead.
- 8x art, the desktop default (2026-11-02): `tools/upscale8x.py` builds `assets/8x`: xBR 2x on the 4x set's xBR 4x for sprites/UI/font (ffmpeg's xBR stops at 4x), and 8x terrain (4096x4096) from the 512 originals through `upscale4x.py`'s `terrain`: the texture is wrapped in 128 px of its own tiling, run through Real-ESRGAN x4plus twice (the second pass on a 32 px margin), brought down to 8x and cropped, so its edges continue into each other with full detail (double Real-ESRGAN drew crisper edges than Lanczos or the anime 2x model from the 4x pass; the originals are soft, so the gain over 2048 is modest). `close_seam` spreads any step the original has at its wrap over 1/16 of the size (smoothed along the edge by 1/512; wider smoothing left the fogs' and clouds' wrap 1.4-1.5x a typical step). The fogs use a padded Lanczos upscale (Real-ESRGAN sharpened their brush smears into streaks); the planet bases are written fully opaque (craters' 1-2 px border alpha, down to 216, drew a dark cross at every wrap). The old crossfade (`tileable`) left the outer 1/8 of each texture at 56-70% of the centre's detail, a soft grid; the 4x set's 2x terrain is rebuilt the same way (`terrain(.., 2)`). World 3's dark band is a lake in the original `green` art that crosses its wrap, not a seam. Normal maps are built at 2048 (`NORMAL_SIZE`). `xbr_scale`/`xbr4` convert palette and grey+alpha PNGs (as oxipng leaves them) to RGBA first: before that, 20 of the 8x UI/sprite files, including the font, lost their transparency and drew black boxes. `asset_scale()` defaults to 8 on desktop; `MB_HD=1` loads the 4x set, `MB_HD=0` the originals. `load_terrain` (main.rs) creates every backdrop texture and normal map through miniquad with repeat wrapping and, for the HD sets, trilinear mipmaps (macroquad allocates no mip levels; generating mips into its textures left the backdrop black; without them large terrain aliased into vertical bands toward the planet's limb). The backdrop shader samples `uv + scroll` on repeating textures instead of `fract()`, which with mipmaps would draw a seam. `load_terrain` loads each file once (the worlds and the menu share bases and decals; a duplicate 4096 texture is ~90 MB), and `predecode_terrain` decodes the HD terrain PNGs on worker threads at startup. Measured 2026-11-02 on this Mac: 4K 60 fps (draw 1.09-1.25 ms; the 4x set 1.01 ms); startup to the first frame 2.3 s (4x 1.0 s); GPU memory (`footprint`, IOAccelerator) 2.3 GB vs 0.46 GB at 4x, most of it the 8x sprite frames; `assets/8x` is 241 MB. The release packages ship only the 8x set (`tools/package-macos.sh`, `tools/package-windows.ps1` drop `assets/4x`); the separate 8x app script is gone. Real-ESRGAN lives at `~/tools/realesrgan/` (the scripts' default) and is required for terrain.

- Bloom (port addition, `settings.txt` `bloom`, on by default) is emitter glow: while the world draws (`Canvas::set_glowing`, off before the HUD), every additive draw (shots, flames, sparks, explosions, the gravity cone) is recorded, plus laser bolts and tower beams (`Canvas::add_glow`); at the blit they are redrawn into a quarter-resolution buffer, blurred (two rounds of a 9-tap separable Gaussian) and added at strength 1.25 (`gfx::Bloom`). Bright clouds and the HUD never glow. Off while the pause popup is up; `MB_BLOOM=0` forces it off.
- Frame rate (port addition): Options > Frame rate cap (60/120/144/165/240 or Unlimited, `settings.txt` `fps`, 0 = Unlimited, default 60; Unlimited has no vsync and ran ~800 fps on this Mac, 165 and 240 measured 165.0 and 240.1) paces drawing; the simulation stays at a fixed 60 Hz. `Play::update` snapshots every drawn position before each step (`Snapshot`) and draws `blend` of the way from it to the current state (camera, scroll, ship, every enemy list, rings); a list whose length changed in the step draws unblended that frame, and bullets step back along their velocity instead. miniquad's macOS frame pacer is a CVDisplayLink created on the main display (60 Hz here, wherever the window is), so on macOS the window runs miniquad's blocking event loop instead (no display-link pacer), paced by `frame_timer` (main.rs): a repeating default-mode run-loop timer at the cap schedules the next frame and posts an empty application event, so the loop waits in `nextEventMatchingMask` between frames. - Audio cleanup (2026-10-30): the game loads `assets/audio/*.wav` from `tools/clean_audio.py`, not `original/audio/`. The originals are 44,200 Hz, and quad-snd converts non-44,100 Hz sound with a nearest-sample resampler whose float32 index jitters (on the music: about 172,000 repeated and 184,000 dropped samples in two minutes, heard as crackle). The script rebuilds hard-clipped runs with a cubic fitted to 4 samples each side (ffmpeg `adeclip` was rejected: it reshaped unclipped transients, -9 to -12 dB on the button click), high-passes the DC at 15 Hz, limits to -1 dBFS with lookahead, resamples to 44,100 Hz (swr, 256 taps), fades effect tails over 5 ms, crossfades the music's loop seam over 20 ms (step 2,981 -> 46) and writes TPDF-dithered 16-bit, deterministically. Unclipped sounds keep their loudness within 0.6 dB; the heavily clipped ones are 1.4-2 dB quieter. `tools/web_audio.py` encodes the MP3s from these; the packages no longer carry `original/audio`.

- Physics particle style (port addition, 2026-11-02; first asked for as BlockYard's "The Formation" gas, then, after several gas versions read as faint, grainy or a "pathetic puff", as massively better particle physics; the user then asked to drop the Formation name): Options > Particle style, Classic or Physics (`settings.txt` `particles=classic|physics`, Classic by default; the old `formation=` key is still read; `MB_PHYSICS=1` forces it on). `src/bursts.rs` (`Bursts`) builds each explosion from four particle kinds, each with its own drag and its own share of the killing shot's velocity (fire 0.35, sparks 0.5, debris 0.45, smoke 0.25, capped at 520 u/s): fire puffs that swell and cool along a blackbody ramp (white only at first, then orange, red), spark streaks drawn along their velocity, spinning debris chips in the colour of what broke, and delayed smoke that swells, lingers and curls through a two-octave curl field (the motion after BlockYard's pulsar wind). Fire and sparks are additive and fed to the bloom; smoke and chips are alpha-blended. An impact sprays sparks on along the shot (a 0.55 rad cone at 0.25-0.7 of its speed) plus ricochets, a flash, chips and a smoke puff; the flamethrower trails fire and smoke. The look (`Look`: smoke colour and opacity, debris colour, weapon tint, heat) comes from the weapon and surface (`Field::bullet` returns `Surface`: Rock(element), Craft, Boss; `impact_look`, `blast_look`): dust for plain rock, soot for fire rock, frost for ice, steam for fire on ice, dark smoke and metal chips for craft and the boss, white-hot laser hits on craft. A kill takes the velocity of a shot that hit within 80 units that step (`Play::hits`); bombs, rams and the ship's death blast still. In this style the events' sprite systems are dropped (`Play::fx`). At most 16,000 particles, drawn in chunks of 800 quads; a busy stage at 4K and zoom 1.5 drew in 0.8 ms on average (60 fps). `MB_BURST_TEST=<frame>` spawns test blasts and impacts beside the ship.
- Stage advance keeps the run: `Play::advance_stage` starts the next stage in the same screen, carrying score, rings, upgrade points, upgrades, lives, bombs and multiplier, like the original's `GameScreen::handleEvent` next-stage case; only the stage's world state restarts.

Controls:
- Defaults (rebindable, see Options > Controls): WASD moves, left mouse fires toward the cursor, Space boosts, right mouse or B bombs, Q or the wheel switches weapon.
- Gravity gun: double-click, or E, while firing.
- Esc on the main menu quits.
- Pause: Esc (or Start/View, or the pause icon) opens; arrows/WASD move the selection, Enter/A activates, Esc/B goes back; mouse clicks activate items. The music, effects and shake sliders are in the selection order (Left/Right adjust a selected slider by 5%) and can be dragged with the mouse.
- Esc goes back one level everywhere, like B on a controller: Stage > World > Mode > Main, the score table and Options > Main, Controls > Options, a pause sub-page > the pause menu > the game; on the main menu it quits. Leaving the HELP tutorial from its pause menu returns to the main menu.
- Controller menus: the D-pad and the left stick move the selection (the stick steps once per push and repeats while held); A activates, B backs out. The focused button is outlined with a 1 px frame, since the original was touch-only and some screens reuse one texture for the up/down states.

Test hooks (env):
- `MB_START=w.s` starts a stage; `MB_WAVE=n` starts at wave n.
- `MB_SHOT` and `MB_SHOT_FRAME` capture a frame and exit.
- `MB_WIDE=0` keeps the original 3:2 view (letterboxed); `MB_WIDE=0 MB_HD=0 MB_RENDER_SCALE=1 MB_BLOOM=0` reproduces the original framebuffer (main menu vs the emulator frame: 7.71 best scan diff, as before the wide view).
- `MB_RENDER_SCALE=<n>` sets the canvas render scale (default: the window's fitted scale, capped at 8; 1 = the original 480x320 framebuffer).
- `MB_RESOLUTION=<WxH|window>` overrides the saved resolution for a run; a preset also resizes the window. `MB_WINDOW` still wins unless `MB_RESOLUTION` is set.
- `MB_HD=0` loads the original art instead of the default `assets/8x/` (1 loads the 4x set; 8 forces the 8x set); emulator-frame comparisons use 0. The web build always loads the originals.
- `MB_FONT_FILTER=linear` switches the bitmap font back to linear filtering.
- `MB_PAUSE=<menu|controls|upgrade|clear|gameover>` opens a pause page for screenshot runs; it starts stage 1.1 when no stage is running, so the popup draws over a game. `original/screenshots/emu/frame_00030.png` is the pause main-page reference. `MB_PAUSE_FRAME=<n>` holds the popup back until frame n, so it draws over a game that has flown in (README `pause.png`: `MB_START=1.1 MB_PAUSE=menu MB_PAUSE_FRAME=420 MB_SHOT_FRAME=480 MB_FPS=60`).
- `MB_LABEL_SCALE=<n>` pins the pause button label scale (default 0.54), for comparing label sizes against the emulator.
- `MB_LABEL_DY=<n>` nudges the pause labels vertically (default 1.0), for matching the emulator's label placement.
- `MB_BG_BASE` / `MB_BG_DECAL_TEX` override the menu backdrop textures (defaults `space4deep`/`fogRed`), for comparing against emulator frames.
- `MB_AUTOFIRE`, `MB_GUN`, `MB_BOMB_AT`, `MB_BOOST_AT`, `MB_WEAPON` and `MB_DRIFT` drive play unattended. `MB_FX_OFF=1` turns Lighting and effects off for a run.
- `MB_ZOOM=<1.0-1.5>` overrides the playfield zoom for a run.
- `MB_ICONS=<0-3>` overrides Options > Button icons (0 Auto, 1 Xbox, 2 PlayStation, 3 Nintendo).
- `MB_FPS=<n>` overrides the 60 Hz frame cap (`0` = uncapped). `MB_PROF=1` prints update/draw CPU per 120 frames; `MB_PROF_FRAMES=n` exits after n frames for benchmarks. Screenshot runs are uncapped unless `MB_FPS` is given, so `MB_SHOT_FRAME` still selects the same state.
- `MB_PAD_LOG` prints controller input. To tell a game bug from a driver one on Windows, run an XInput reader (`XInputGetState` on xinput1_4.dll) alongside and compare.
- `MB_MENU=<main|mode|options|controls|scores|scores-arcade|scores-survival|scores-global>` opens a menu screen directly, for captures (`help` = `controls`).

- `MB_FOCUS=<n>` shows the controller focus frame on the nth menu button in `MB_MENU` captures.
